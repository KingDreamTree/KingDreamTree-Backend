# 검토 위원회 (Review Council)

해커톤 우승을 목표로 이 프로젝트를 적대적으로 검토하는 5인 페르소나.
의장·서기는 오케스트레이터(메인 세션)가 맡는다 — 슬롯을 회의록 작성에 쓰지 않기 위해서.

| 파일 | 페르소나 | 담당 리스크 |
|---|---|---|
| `judge.md` | 해커톤 심사위원장 | 점수. 떨어뜨릴 이유 |
| `tech-lead.md` | 개발 전문가 / 테크리드 | 코드가 실제로 깨지는 곳 |
| `sre-demo.md` | SRE / 데모 운영 | 발표 당일 장애 |
| `ethics-privacy.md` | 신체이미지 윤리 + 개인정보 | 킬러 질문 방어 |
| `exercise-science.md` | 운동생리학 | 루틴이 사람을 다치게 하나 |

## 진행 규칙

1. **1라운드는 독립.** 서로 뭐라 했는지 모른 채 각자 작성한다. 안 그러면 첫 발언자에게 끌려간다
2. **근거 없는 발언 금지.** 모든 지적에 `파일:줄`. 안 읽었으면 "확인 못 함"이라고 쓴다
3. **2라운드는 교차 반론.** 다른 위원의 P0에 반대할 근거가 있으면 반드시 낸다
4. **반대 의견을 봉합하지 않는다.** 합의 안 된 건 회의록에 "미해결"로 남긴다
5. 모든 항목은 **P0/P1/P2 + 소요 시간 + 안 고치면 나는 일**로 끝난다

## 산출물

- `docs/review-council-<날짜>.md` — 회의록 (라운드별 발언 + 미해결 쟁점)
- `docs/decisions-<날짜>.md` — 최종 수정사항

정의를 방금 만든 세션에서는 범용 에이전트에 이 파일을 읽혀서 페르소나를 주입한다.
