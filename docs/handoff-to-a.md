## ① VLM 입력 형식 확정 — 크롭 파일 만들지 마세요 ⭐

`work-b.md §9`에서 "B가 결정 → A에게 알려주면 A가 파일을 만듦"으로 남아 있던 항목입니다.

**결정: 크롭 ❌ → 원본 사진 + seg_map 하이라이트 ✅**

| 항목 | 결정 |
|---|---|
| `body_part_segment.crop_path` | **NULL로 두세요.** 부위별 크롭 PNG를 생성/업로드하지 않습니다 |
| B가 실제로 쓰는 것 | `photo.storage_path` (원본) + `segmentation.map_path` (라벨 맵) |
| 하이라이트 이미지 | **B가 직접 만듭니다.** A는 만들지 않아도 됩니다 |

**이유**: 부위를 잘라내면 VLM이 신체 비율의 맥락을 잃습니다. "어깨가 좁다"는 판단은 몸통 전체 대비 비율이 보여야 가능합니다. 원본에 해당 부위만 하이라이트하면 맥락과 지목을 동시에 얻습니다.

**A가 얻는 것**: 부위 9개 × 사진 2장 = 18개 크롭 파일 생성·업로드 로직이 통째로 불필요해집니다.

**B가 필요한 것**: `segmentation.map_path`의 라벨 맵 PNG + `label_map` JSON. 이건 이미 계약에 있습니다.

## ② `TOO_SMALL` 판정 유지해 주세요 — 의미가 하나 늘었습니다

현재 `body_part_segment.is_valid=false` + `invalid_reason='TOO_SMALL'` 로직은 **그대로 두시면 됩니다.** 변경 요청 아닙니다.

다만 B쪽에서 이 신호를 **"실패"가 아니라 "옷에 가려짐 신호"로도 해석**합니다. 정상 인체에서 상완 면적 ≈ 전완 면적 × 1.1~1.3인데, 상완만 현저히 작으면 소매에 가려진 것이기 때문입니다.

→ **A 작업 없음.** 다만 나중에 임계값을 조정하실 때 B에게 알려주세요. 해석이 같이 흔들립니다.

## ③ 레퍼런스는 PRESET 사용 — 복장 변수 제거

`analysis_session.reference_source`를 `PRESET`으로 쓰는 것을 전제로 B 로직을 짰습니다. 레퍼런스 사진의 복장이 변수가 되면 비교 기준이 흔들려서입니다. 사용자 업로드 레퍼런스도 스키마상 가능하지만, 해커톤 데모는 PRESET으로 가는 걸로 이해하고 있습니다. **다르면 알려주세요.**
