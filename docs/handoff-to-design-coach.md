# 디자인 전달 — 운동 후 코치 대화 화면

> **작성**: B파트 · 2026-08-15
> **기존 기획**: 캐릭터가 피드백을 받는 **대화창 하나**
> **바뀐 것**: 여러 번 주고받는 대화 + 마지막에 «바뀐 루틴 요약 카드»

---

## 1. 무엇이 달라졌나 — 한눈에

```
기존)   운동 완료 → [ 캐릭터: 오늘 어땠어요? ]  → 사용자 입력 → 끝
                     (한 번 받고 저장)

변경)   운동 완료 → 대화 (평균 2~4턴, 최대 8턴)
                     ↓
                  «변경 요약 카드» + [적용] / [그대로 둘게요]
                     ↓
                  다음 운동부터 루틴이 실제로 바뀜
```

**핵심 차이**: 한 번 받고 끝이 아니라 **코치가 되묻고, 제안하고, 합의한 뒤
무엇이 왜 바뀌는지 카드로 보여줍니다.**

바뀐 이유: 피드백을 한 줄만 받으면 "무릎이 아팠어요" 를 코치가 마음대로
해석해 루틴을 고칩니다. 되물어서 정도를 확인해야 안전하고, 사용자가 **동의한
변경만** 적용되어야 신뢰가 생깁니다.

---

## 2. 필요한 화면 6가지

### ① 대화 진입 — 코치가 먼저 말을 겁니다

운동 완료 직후. **사용자가 먼저 쓰지 않아도 되게** 코치 인사가 먼저 옵니다.

```
🧑‍🏫  오늘 하체 A 완료하셨네요! 어떠셨어요?
     힘들었던 운동이나 불편한 곳이 있으면 편하게 말씀해주세요.

                                       [ 입력창 ]  [보내기]
                                       [ 오늘은 괜찮았어요 ]  ← 빠른 종료
```

- 캐릭터는 기존 자산 그대로 써도 됩니다
- **「오늘은 괜찮았어요」 같은 빠른 종료 버튼**을 주세요 — 매번 타이핑을
  요구하면 완료율이 떨어집니다

### ② 대화 중 — 일반 채팅

```
🧑‍🏫  무릎이 아프셨군요. 통증이 운동을 멈출 정도였나요,
     아니면 살짝 불편한 정도였나요?

                          살짝 불편한 정도?  계속 신경은 쓰였어  🙋
```

- 말풍선 좌/우 구분
- **로딩 인디케이터 필요** — 코치 응답에 2~5초 걸립니다 (AI 호출)
- 대화는 보통 2~4턴이면 끝납니다

### ③ 도구 이벤트 배지 — 대화 중에 뜹니다 ⭐ 신규

코치가 **행동을 실행하면** 말풍선 아래에 배지가 붙습니다.

```
🧑‍🏫  알려주셔서 다행이에요. 다음부터 부담이 적은 운동으로 바꿔볼게요.

     ┌────────────────────────────┐
     │ ⚠️  무릎 → 주의 부위 등록됨  │   ← 배지
     └────────────────────────────┘
```

배지 종류는 3가지입니다.

| 배지 | 언제 | 톤 |
|---|---|---|
| ⚠️ 주의 부위 등록 | 통증을 말했을 때 | 경고 색 (주황) |
| 🔄 운동 교체 | 다른 운동으로 바꿀 때 | 중립 |
| 📊 강도 조정 | 세트·횟수를 바꿀 때 | 중립 |

> ⚠️ **주의 부위 등록은 [적용] 버튼을 기다리지 않고 즉시 반영됩니다.**
> 안전은 버튼 뒤에 두지 않는다는 원칙입니다. 배지 문구도 "등록됨"(완료형)
> 으로 써주세요 — "등록할까요?" 가 아닙니다.

### ④ 마지막 요약 카드 — 이번 화면의 핵심 ⭐ 신규

대화가 끝나면 코치의 마지막 말과 함께 **카드**가 뜹니다.

```
🧑‍🏫  좋아요, 정리해드릴게요 👇

     ┌──────────────────────────────────────────┐
     │  다음 운동부터 바뀌는 것                   │
     │                                          │
     │  🔄  스쿼트 → 레그프레스                  │
     │      무릎에 부담이 적은 운동으로 바꿨어요   │
     │                                          │
     │  ⚠️  무릎 → 주의 부위 등록                │
     │      앞으로 모든 루틴에 반영돼요           │
     │                                          │
     │  ─────────────────────────────────────   │
     │  통증이 계속되면 운동을 중단하고           │
     │  전문가와 상담하세요.                     │
     └──────────────────────────────────────────┘

        [ 이대로 적용할게요 ]   [ 그대로 둘게요 ]
```

**항목마다 «무엇이» + «왜» 가 쌍으로 옵니다.** 이유 없이 무엇만 보여주면
"AI 가 마음대로 바꿨다"로 읽힙니다. 두 줄 구조를 꼭 지켜주세요.

- 굵은 줄 = 무엇이 바뀌나 (`what`)
- 회색 줄 = 왜 바뀌나 (`why`)
- 안전 문구는 통증이 있었을 때만 붙습니다

### ⑤ 적용 완료

```
     ✅  다음 운동부터 새 루틴으로 진행돼요
         [ 바뀐 루틴 보기 ]
```

변경이 없었던 경우도 있습니다 (대화만 하고 바꿀 게 없을 때):

```
     💬  오늘 대화는 기록해뒀어요. 루틴은 그대로입니다
```

### ⑥ 대화 종료 상태 — 입력창 잠금

카드가 뜨면 **대화는 끝난 것**입니다. 입력창을 비활성화하거나 숨겨주세요.
[적용] / [그대로 둘게요] 중 하나를 고르는 단계입니다.

## 3. 프론트 개발 참고사항

### 대화 상태를 프론트가 들고 있습니다

서버가 대화를 저장하지 않습니다. **응답의 `messages` 배열을 그대로 보관했다가
다음 요청에 다시 보내야** 대화가 이어집니다.

```
POST /coach-chat
  { "messages": [ …이전 전체…, { "role": "user", "content": "새 발화" } ] }

응답:
  { "reply", "messages", "tool_events", "finalized", "turn", "max_turns" }
                ↑ 이걸 통째로 보관
```

> ⚠️ `messages` 안에는 화면에 **표시하지 않는 항목**도 들어 있습니다
> (도구 호출 기록 등). 화면에는 `reply` 만 말풍선으로 그리고, `messages` 는
> 그대로 들고만 있으면 됩니다.

### 화면에 그릴 것 / 들고만 있을 것

| 필드 | 용도 |
|---|---|
| `reply` | **말풍선으로 표시** |
| `tool_events` | **배지로 표시** (③) |
| `finalized` | 있으면 **카드 표시 + 대화 종료** (④) |
| `messages` | 표시 안 함. 다음 요청에 그대로 되돌려보냄 |
| `turn` / `max_turns` | 표시 안 해도 됨 (아래 참고) |

### 턴 제한 — 8턴

`max_turns` 는 8입니다. 초과하면 코치가 **자동으로 마무리 카드**를 냅니다.
진행 표시(3/8 같은)는 **넣지 않는 걸 권합니다** — 대화를 서두르게 만듭니다.
보통 2~4턴이면 끝나서 사용자가 한도를 볼 일이 거의 없습니다.

### [적용] 버튼

```
POST /coach-chat/apply
  { "messages": [ …전체 히스토리… ] }
```

- 응답의 `no_change: true` 면 ⑤의 "루틴은 그대로" 문구
- 실패해도 **이전 루틴은 그대로 살아 있습니다** — 에러 토스트만 띄우면 됩니다

### 이탈 처리

대화 중 사용자가 나가도 괜찮습니다. **[적용] 을 안 눌렀으면 루틴은 안 바뀝니다.**
(단, 주의 부위 등록은 이미 반영됨 — ③ 참고)

별도의 "저장 안 됨" 경고는 필요 없습니다.

## 4. 톤 & 문구 가이드

코치 말투는 서버가 만듭니다. 디자인에서 맞춰주실 부분:

| | |
|---|---|
| 성격 | 지시하지 않고 **제안**합니다 ("바꾸세요" ❌ → "바꿔볼까요?" ⭕) |
| 길이 | 한 번에 2~4문장. 말풍선이 길어지지 않습니다 |
| 첫 마디 | 완료를 먼저 인정합니다 ("오늘도 끝까지 하셨네요") |
| 통증 | 절대 가볍게 넘기지 않습니다. 되묻고, 안전 문구를 붙입니다 |

> 근거: 운동 코칭 챗봇 연구(GPTCoach, Stanford CHI 2025)의 **동기부여 면담**
> 전략을 따랐습니다 — 지시형보다 끌어내는 대화가 행동 변화에 효과적입니다.

## 5. 디자인 체크리스트

- [ ] 코치 인사가 **먼저** 뜨는 진입 화면
- [ ] 「오늘은 괜찮았어요」 빠른 종료 버튼
- [ ] 응답 대기 로딩 인디케이터 (2~5초)
- [ ] 도구 이벤트 배지 3종 (주의 부위 / 운동 교체 / 강도 조정)
- [ ] 요약 카드 — 항목마다 **무엇 + 왜** 두 줄
- [ ] 카드 하단 안전 문구 영역 (통증 시에만)
- [ ] [이대로 적용할게요] / [그대로 둘게요]
- [ ] 카드 표시 후 **입력창 비활성화**
- [ ] 적용 완료 화면 + 「바뀐 루틴 보기」
- [ ] 변경 없음 케이스 문구

## 6. 참고 — 실제 대화 예시 (실제 GPT-4o 응답)

```
🧑‍🏫  오늘 고블렛 스쿼트를 하면서 무릎이 좀 아프셨군요.
     통증이 운동을 멈출 정도였나요, 아니면 살짝 불편한 정도였나요?

                  운동 멈출 정도는 아니고 살짝 불편한 정도? 🙋
                          근데 계속 신경 쓰이긴 했어

🧑‍🏫  무릎이 살짝 불편하셨군요. 무릎에 부담을 덜 주는 운동으로
     바꿔보는 게 좋을 것 같아요. 바디웨이트 리어 런지나
     불가리안 스플릿 스쿼트로 교체해볼까요?

                                      응 그렇게 바꿔줘 🙋

🧑‍🏫  운동 루틴을 조정했습니다. 무릎의 불편함이 계속되면 운동을
     중단하고 전문가와 상담하세요. 다음 운동도 화이팅입니다!

     [ 🔄 운동 교체 ]  [ ⚠️ 주의 부위 등록됨 ]

     ┌─────────────────────────────────────┐
     │  다음 운동부터 바뀌는 것              │
     │  🔄 고블렛 스쿼트 → 바디웨이트 리어 런지│
     │     무릎에 부담을 덜 주기 위해         │
     │  ⚠️ 무릎에 주의 필요                  │
     │     스쿼트 시 무릎 불편함              │
     └─────────────────────────────────────┘
        [ 이대로 적용할게요 ]  [ 그대로 둘게요 ]
```
