# 디자인 전달 — step 3/3 인바디 정보 입력

> **대상 화면**: step 3/3 «인바디 정보 입력»
> **작성**: B파트 · 2026-08-13
> 현재 와이어프레임의 필드를 **확정된 백엔드 스키마**에 맞춰 조정 요청드립니다.

---

## 1. 먼저 — 단위 오류 1건

| 현재 | 수정 |
|---|---|
| 체지방률(**kg**) | 체지방률(**%**) |

체지방량(kg)과 체지방률(%)은 다른 값입니다. 지금 화면엔 둘 다 kg으로 되어 있어 사용자가 같은 값을 두 번 입력하게 됩니다.

---

## 2. 최종 필드 목록

### 그룹 A — 기본 정보 (신규)

| 필드 | 단위 | 우선순위 | 비고 |
|---|---|---|---|
| **신장** | cm | 🔴 **필수** | 없으면 SMI·BMI 검증이 전부 동작 안 함 |
| 나이 | 세 | 🟡 선택 | |
| 성별 | 남 / 여 | 🟡 선택 | 토글 또는 세그먼트 컨트롤 |
| 측정일 | YYYY-MM-DD | 🟡 선택 | |

> 🔴 **신장은 반드시 추가해 주세요.** 현재 화면엔 없는데, 골격근량을 체격으로 나눈 **SMI**가 부위별 진단의 핵심 지표라 신장이 빠지면 계산 자체가 불가능합니다.

### 그룹 B — 체성분 (기존 「골격근·지방/비만 분석」)

| 필드 | 단위 | 상태 |
|---|---|---|
| 체중 | kg | 유지 |
| 골격근량 | kg | 유지 |
| 체지방량 | kg | 유지 |
| BMI | kg/m² | 유지 |
| 체지방률 | **%** | **단위 수정** |
| 제지방량 | kg | **신규** |
| 기초대사량 | kcal | **신규** |

### 그룹 C — 부위별 근육량 (기존 유지, 5개 그대로)

오른팔 / 왼팔 / 몸통 / 오른다리 / 왼다리 — 전부 kg

### 그룹 D — 부위별 체지방량 (신규, 5개)

그룹 C와 **동일한 5부위**, 단위 kg. 나란히 2열로 배치하면 좋습니다.

> 그룹 C(근육)와 D(지방)를 같이 받아야 "팔은 근육 부족인데 몸통은 지방 과다" 같은 부위별 판단이 가능합니다.

### 그룹 E — 계산값 (읽기 전용, 입력칸 아님)

| 항목 | 단위 | 설명 |
|---|---|---|
| **SMI** | kg/m² | 골격근량 ÷ 신장². 서버가 계산해서 내려줍니다 |

입력 필드가 아니라 **결과 표시**입니다. 회색 텍스트나 별도 배지로, 사용자가 수정할 수 없다는 게 보이게 해주세요. 사용자가 골격근량이나 신장을 고치면 **즉시 다시 계산돼서 내려옵니다.**

---

## 3. 필요한 화면 상태 4가지

현재 와이어프레임은 «정상» 하나만 있습니다. 백엔드가 아래 4가지를 내려주므로 각각 디자인이 필요합니다.

### ① 정상
현재 디자인대로. 값이 채워진 상태.

### ② 검증 경고 (WARN) — 🔴 가장 중요

서버가 값을 검증해서 **의심스러운 필드를 지목**해 내려줍니다.

예: 체지방량이 12kg인데 21kg으로 잘못 읽히면 → **체중·제지방량·체지방률 3개 필드에 동시에 경고**가 붙습니다.

> ⚠️ **주의할 특성**: 경고는 "이 칸이 틀렸다"가 아니라 **"이 값들이 서로 안 맞는다"**는 뜻입니다.
> 위 예시에서 실제로 틀린 건 «체지방량»인데, 경고는 그와 연결된 **다른 3개 칸**에 뜹니다.
>
> 그래서 경고를 칸 하나에 고립시켜 표시하면 사용자가 엉뚱한 값을 고칩니다.
> **관련 필드를 하나의 그룹으로 묶어** "이 값들끼리 계산이 맞지 않아요"로 보여주는 편이 좋습니다.
> 어떤 칸이든 고쳐서 계산이 맞으면 경고는 전부 사라집니다 (실측 확인).

필요한 디자인:
- 해당 입력칸 테두리 강조 (주황 계열)
- 칸 아래 한 줄 메시지 — 서버가 문구까지 보냅니다
  > *"체지방률 불일치 — 계산값 33.07 vs 추출값 18.90"*
- 상단에 "확인이 필요한 항목이 N개 있습니다" 요약 배너

> ⚠️ **경고가 있어도 다음 단계로 넘어갈 수 있어야 합니다.** 실제로 좌우 비대칭이 심한 사람도 있어서, 막지 않고 알려주기만 합니다.

### ③ 입력 범위 오류

사용자가 직접 고친 값이 저장 가능 범위를 벗어나면 서버가 거부합니다 (예: 체중 500kg).

- 인라인 에러 (빨강) + 저장 실패 표시
- ②의 «경고»와 시각적으로 구분되어야 합니다. **경고는 통과 가능, 오류는 저장 불가**입니다.

참고 범위: 신장 120~220cm · 체중 25~250kg · BMI 10~60 · 체지방률 1~70% · 골격근량 10~60kg · 기초대사량 500~5000kcal

### ④ OCR 실패 → 빈 폼 (수기 입력)

결과지 인식이 실패해도 **사용자가 직접 전부 입력해서 진행할 수 있습니다.** 백엔드가 지원합니다.

- 안내 문구: *"결과지를 읽지 못했어요. 직접 입력하시거나 건너뛸 수 있습니다."*
- 빈 입력칸 + **「건너뛰기」 버튼**

> 💡 인바디는 **선택 입력**입니다. 없어도 체형 분석과 4주 루틴은 정상 동작합니다. 이 화면에서 사용자를 막으면 안 됩니다. 「건너뛰기」가 항상 보여야 합니다.

---

## 4. 「다음 단계」 버튼 동작

이 버튼을 누르면 서버에 **"사용자가 확인했음"**이 기록됩니다. 그래서 문구를 조금 명확히 하면 좋겠습니다.

| 현재 | 제안 |
|---|---|
| 다음 단계 | **확인 완료** 또는 **이 값으로 진행** |

누른 뒤에는 이 결과지가 «확인됨» 상태가 되고, 이후 화면에서 확인 시각을 보여줄 수 있습니다.

---

## 5. 참고 — 데이터가 어디서 오는지

```
결과지 사진 업로드
   → AI가 값 추출 (수 초 소요, 로딩 필요)
   → 서버가 자동 검증 (체중 = 체수분+단백질+무기질+체지방 등 6종)
   → 이 화면에 «값 + 경고» 표시
   → 사용자가 고치면 즉시 재검증 + SMI 재계산
```

추출 로딩 화면이 별도로 필요합니다 (업로드 직후 ~수 초).

원본 추출값은 사용자가 수정해도 **서버에 그대로 보존**됩니다. 나중에 AI 정확도를 측정하기 위해서이고, 화면에 보일 필요는 없습니다.
