# 리팩토링 정리 — 캐시 · 프롬프트 (2026-09-12)

> 📌 **한 줄 요약** — 두 문제 모두 «겉으로 보인 원인» 이 진짜 원인이 아니었다. Day 버그는 캐시가 아니라 **Day 를 횟수로 역산**한 탓이었다. 같은 멘트는 규칙이 부족해서가 아니라 **모델이 9장을 한 번에 쓰면 첫 문장을 따라가는** 탓이었다. 그래서 둘 다 규칙을 더 넣지 않고 **구조를 바꿨다.**

---

# 1. 캐시 — 같은 브라우저에서 Day 가 혼자 올라가던 문제

## 문제

같은 브라우저로 오래 쓸수록 게이지의 Day 가 앞서갔다. 처음 들어왔는데 Day 4 로 나오고, 코치는 방금 한 운동이 아니라 다음 Day 운동을 «오늘 한 운동» 으로 말했다.

## 진짜 원인

브라우저 캐시가 아니었다 (서버에 응답 캐시가 없다). **Day 를 «완료 횟수 + 1» 로 계산**했기 때문이다.

- 완료 기록이 한 번이라도 중복되면 Day 가 한 칸 밀리고, 그 밀림이 **계속 쌓인다**
- 중복은 버튼 연타와 **«완료 누르고 바로 새로고침»** 에서 생겼다 — 새로고침하면 연타 잠금이 풀린다
- 실측: 완료 기록 206건 중 60초 안에 연속으로 들어간 기록 48건

## 바꾼 구조

| | 전 | 후 |
|---|---|---|
| Day 계산 | 완료 횟수 + 1 | **마지막 완료 기록** 기준 |
| 중복 방지 | 연타 잠금 (새로고침하면 풀림) | 새로고침해도 남는 잠금 (sessionStorage) |
| 이미 쌓인 중복 | 방치 | 정리 스크립트 `scripts/dedupe_workout_logs.py` (미리보기 → 확인 후 삭제) |

**왜 이렇게 바꿨나** — 횟수는 한 번 틀어지면 계속 틀린다. «마지막으로 완료한 Day» 는 사용자가 실제로 한 Day 라서 틀어질 수가 없다.

# 2. 프롬프트 — 부위 카드가 같은 멘트로 나오던 문제

## 문제

부위 카드 9장이 부위 이름만 바뀐 같은 문장이었다. 운영 세션 5회 × 9장 = 45장 중 **22장이 같은 문장 두 개**였다.

```
□ 목표 체형과 비교해 큰 차이가 없습니다.         ← 12장
□ 목표 체형보다 근육 윤곽이 덜 드러나는 편입니다. ← 10장
```

## 진짜 원인

1. **규칙이 너무 많았다** — 금지문 56개에, 서로 부딪히는 지시도 있었다. 모델은 긴 규칙 중 일부만 지킨다
2. **예시 문장을 모든 카드가 같이 봤다** — 그래서 그대로 복사됐다
3. **gpt-4o 는 9장을 한 응답에 쓰면 첫 카드의 문형을 따라간다** — 이게 핵심이다. 규칙으로는 이길 수 없었다

## 무엇을 시도했나 — 같은 운영 세션, 5회씩

| 시도 | 결과 |
|---|---|
| 카드마다 시작 틀을 코드가 배정 | 겹침은 줄었지만 **비문** («가장 크게 다른 곳은 오른쪽 상완은 …») |
| 틀 제거 | 전 카드가 «X는 목표 체형에 비해 …편입니다» 로 수렴 |
| 온도 올리기 | 문장보다 **판정이 먼저 흔들렸다** (같은 사진에 «덜 발달» ↔ «두껍다») |
| 판정과 글쓰기를 두 번 호출로 분리 | 호출이 늘어도 한 회차가 «현재 체형은 …» 으로 수렴 |
| **gpt-4.1 로 교체** | 부위마다 다른 관찰로 문장을 연다 → **채택** |

## 바꾼 구조

**① 부위 카드 모델만 gpt-4.1** (`vlm.PART_MODEL`) — 종합 진단·OCR·스크리닝·루틴은 gpt-4o 그대로 둔다. 토큰 단가도 gpt-4o 보다 낮다.

**② 규칙은 짧게, 문장 구조는 정하지 않는다** — 3,886자 → **1,737자**. «두 문장: 지금 / 목표» 같은 구조 지정과 예시 문장을 없앴다. 대신 부위마다 «볼 것» 지점만 주고 상담하듯 쓰게 한다.

**③ 규칙은 한 벌** — 웹캠·사진 두 경로가 같은 규칙을 쓴다. 전에는 파일이 따로라서 한쪽만 고쳐지는 사고가 반복됐다.

**④ 모델이 계속 어기는 건 코드로 막는다** — «사용자의 …», 운동 권유, 종목 이름은 응답을 받은 뒤 코드가 걷어낸다.

## 결과 — 실제 DB · 실제 코드, 운영 세션 5회 × 9장

수치는 `scripts/eval_diagnosis.py` 측정 로그로 다시 확인한 값이다 (2026-09-12).

| | 개편 전 | 틀 배정 (중간) | **최종** |
|---|---|---|---|
| 같은 문장 반복 («큰 차이가 없습니다» 등) | 22/45 | — | **0** |
| 한 회차 안 문형반복 (중앙값) | 20 | 8 | **1** |
| 규칙 위반 합계 (중앙값) | — | 14 | **1** |
| «사용자의 …» | — | 29 | **0** |

최종 카드 예시 (몸통):
> 어깨에서 허리로 이어지는 선이 목표 체형에 비해 완만하게 좁아지는 편이며, 허리 옆선이 안으로 들어가지 않고 바깥으로 볼록하게 나와 있습니다. 가슴과 복부의 앞뒤 두께가 두드러져 전체적으로 직사각형에 가까운 몸통 형태로 보입니다.

좌우 쌍(왼쪽·오른쪽 상완 등)은 비슷하게 나올 수 있다. 실제 몸도 좌우가 비슷하므로 정상으로 본다.

## 프롬프트 관리 — 코드에서 DB 로

| | 전 | 후 |
|---|---|---|
| 위치 | 코드 파일 안 | `prompt_version` 테이블 (프롬프트 13개) |
| 고치는 법 | 코드 수정 + 배포 | SQL 한 장 (`scripts/prompt_version.py new` 가 생성), 배포 없음 |
| 추적 | 어느 문구로 나온 결과인지 모름 | 진단 결과마다 버전 기록 (`prompt_version` 컬럼) |
| DB 장애 | — | 마지막으로 읽은 값으로 계속 동작 |

**왜 이렇게 바꿨나** — 문구 한 줄 고치는데 배포가 필요했고, 결과가 나빠도 어느 문구 때문인지 알 수 없었다. 이번 개편도 `part.rules` v1 → v2 를 SQL 로 올렸다. 되돌리려면 `prompt_version.py activate part.rules 1`.
