# F10 운동 추천 로직 설계서 — "어떻게 운동을 추천하나요"에 대한 단계별 답

> **작성**: B파트 · 2026-08-14 (v2 — 근거 감사 후 전면 개정)
> **목적**: 추천의 모든 단계에 출처를 붙이고, PM 결정 항목 D1~D9 확정
> v1 대비 변경: 체지방률 컷오프 교체(H3) · LLM 중량 추정 폐기(H2) · 운동 선택 제약(H1)

---

## 0. 설계 원칙 — 왜 이 파이프라인은 허점이 없는가

추천의 모든 단계는 둘 중 하나여야 합니다.

> **(a) 출처가 있는 결정론적 규칙 (코드)** — 가이드라인·논문·API 데이터에서 옴
> **(b) "무엇을 골라도 틀리지 않는" 후보 집합 안에서의 LLM 선택**

LLM의 재량에 근거를 요구하지 않습니다 — **재량 자체를 없앱니다.**
"왜 이 운동인가요?"라는 질문에 "AI가 골랐어요"는 답이 아니지만,
"ACSM 초보자 권고에 맞는 후보를 코드가 거르고, 그 안에서 AI가 사용자 진단에
맞춰 골랐어요"는 답이 됩니다.

---

## 1. 파이프라인 — 질문 8개, 답 8개

사용자가 "어떻게 추천하나요"라고 물으면, 실제로는 8개의 하위 질문입니다.
각각에 결정 주체와 출처를 붙였습니다.

### Q1. 일주일에 며칠 운동하나?

| | |
|---|---|
| **결정** | 사용자가 1~7일 선택. UI에 "권장" 배지는 3일 |
| **주체** | 사용자 (시스템은 강제하지 않음) |
| **근거** | ① ACSM 2009: 초보자 주 2~3일 권고 ② Schoenfeld 2019 메타분석: **총볼륨이 같으면 빈도는 근성장에 무관** → 빈도를 라이프스타일에 맡겨도 과학적 손실이 없고, 지속률이 더 중요 ③ 7일 선택 시 6일+능동회복 변환 (회복이 적응의 조건) |

### Q2. 살을 빼는 몸인가, 키우는 몸인가? (L0 모드)

| | |
|---|---|
| **결정** | `CUT`(감량 병행) 또는 `BALANCE`(기본). **코드가 인바디 실측으로만 판정** |
| **판정 규칙** | **체지방률이 1차**: 남 ≥25% / 여 ≥36% → CUT, 그 외 BALANCE (JCEM 2025 %BF 기반 과체중 정의). 체지방률을 못 읽었을 때만 폴백 → ① `체지방량 ÷ 체중 × 100` 파생값 ② 그래도 없으면 BMI ≥ 25 (대한비만학회). **인바디 없으면 무조건 BALANCE** |
| **근거** | ① Spot reduction 부정 (메타분석 2021 · Ramírez-Campillo 2013 · Vispute 2011): 부위 운동으로 부위 지방을 뺄 수 없으므로 "지방"은 전역 판단이어야 함 ② 사진으로 체지방률을 재는 것은 방어 불가 → 실측 있을 때만 모드 전환 ③ **BMI를 1차로 쓰지 않는 이유는 §2-H8 참조** |
| **CUT 골격** | 전신 근력 유지(감량기 근육 보존) + 유산소 슬롯. 유산소량 산식: ACSM Donnelly 2009 — 주 150분(체중 유지)~250분+(유의미 감량). 근력일 후 15~20분 + 휴식일 걷기 30~40분 권장 = 주 150분 이상 도달 |
| **주의** | CUT에서도 **부위 가중(Q5)은 그대로 동작** — 전신 근력일의 운동 선택에서 약점 부위가 우선됨 |

### Q3. 어떤 분할 구조로 나누나? (L1 골격)

| | |
|---|---|
| **결정** | 일수별 분할 템플릿, 코드 고정 (`routine_templates.py`): 1~3일 전신 / 4~5일 상·하 분할 / 6일 PPL / 7일 = 6일+능동회복 |
| **근거** | ACSM 2009 Position Stand: 초보 전신 2~3일, 중급 이상에서 분할 3~4일+. 같은 근육군 연속 배치 금지(회복 48시간)도 템플릿이 구조적으로 보장 |
| **LLM 개입** | 없음. LLM에 맡기면 휴식일 누락·근육군 연속 배치 사고가 남 |

### Q4. 세션마다 몇 세트, 몇 회?

| | |
|---|---|
| **결정** | 슬롯(근육군 단위)에 세트·횟수·휴식 **코드 고정**: 3세트 × 8~15회, 휴식 60~90초 |
| **근거** | ACSM 2009 초보자 권고: **1~3세트 × 8~12회(60~70% 1RM), 복합·단순 관절 운동 병용** — 현 템플릿(3×8~15)이 권고 범위 안. 코어·종아리 15회는 지구성 근육 특성 반영(ACSM 근지구력 15~25회 권고 범위) |
| **감사 결과** | 수치는 이미 부합했으나 **출처가 코드에 명기돼 있지 않았음** → 주석 추가 예정 (H4) |

### Q5. 어느 부위를 강조하나? (L2 가중 — 진단이 쓰이는 곳)

| | |
|---|---|
| **결정** | F09 `priority_parts` 상위 부위 → 해당 근육군 슬롯에 **주간 +2~4세트 가산**. 부위당 주간 총 세트 상한 20세트 |
| **근거** | Schoenfeld 2017 볼륨 도즈-리스폰스 메타분석: 주당 세트 증가당 근비대 +0.38%, **~10세트/주 부근까지 뚜렷한 이득**, 20세트 초과는 근거 부족 → 가산은 이 범위 안에서만. 초보는 낮은 볼륨에도 반응(ACSM: 초보 단일세트도 유효)하므로 비우선 부위도 기본 볼륨으로 충분 |
| **좌우 비대칭** | F08 좌우 차이가 클 때 단측(single-arm/lunge) 운동을 후보에 포함. ⚠️ 이건 RCT 근거가 아니라 **전문가 관행(NSCA 계열)** 수준 — 과잉 주장 금지, "균형 운동을 권합니다" 문구까지만 |
| **핵심 논리** | 진단은 부위의 **포함/제외가 아니라 볼륨 가중치** → 진단 실패·의류 가림·인바디 없음 어떤 조합에도 루틴이 깨지지 않음 |

### Q6. 구체적으로 어떤 운동을 주나? ← 이전 설계 최대 허점

| | |
|---|---|
| **결정** | **LLM 자유 기입 폐기.** ExerciseDB에서 코드가 후보를 거르고, LLM은 **후보 목록 안에서 exerciseId로만 선택** |
| **필터 규칙 (코드, 순서대로)** | ① 슬롯 근육군 ↔ `targetMuscles` 매핑 (§3 표) ② 사용자 장비 ↔ `equipments` ③ `exerciseType` (근력 슬롯=STRENGTH, CUT 유산소 슬롯=CARDIO) ④ 초보 부적합 제외 목록 (§D8) ⑤ **복합운동 우선 정렬**: `bodyParts`≥2 또는 `secondaryMuscles` 존재 시 상위 배치 |
| **근거** | ① 운동↔근육 매핑은 **ExerciseDB 데이터** (우리가 주장하지 않음 — 데이터 출처 명시 가능) ② 복합운동 우선: ACSM 2009 "초보자에게 다관절 운동 강조" ③ LLM이 후보 밖 운동을 낼 수 없으므로 환각 구조적 차단 + exerciseId로 이미지/영상 연결 |
| **LLM의 역할** | 후보 중 다양성·중복 회피·사용자 맥락(진단 문구와의 일관성) 반영해 선택. **어느 것을 골라도 규칙 위반이 아닌 집합** 안에서만 |

### Q7. 무게는 몇 kg? ← 이전 설계 두 번째 허점

| | |
|---|---|
| **결정** | **절대 kg 추정 폐기.** RIR 기반 처방으로 교체: *"8~12회를 하고 2회쯤 더 할 수 있을 것 같은 무게"* (RIR 2) |
| **근거** | ① 사진·인바디로 1RM을 추정할 방법이 없음 — LLM의 kg 추정은 어떤 출처로도 방어 불가 ② RIR/RPE 자가조절 처방은 문헌 정립됨 (Zourdos 2016 RIR 척도 · Helms 자가조절 프레임워크). 초보자의 RIR 추정이 부정확하다는 한계도 문헌에 있으므로 "정확한 무게"가 아니라 "멈추는 기준"으로만 안내 |
| **스키마 영향** | `weight_kg`는 nullable 유지(향후 기록 기능용), 생성 시점엔 채우지 않음. 프론트: 무게 칸 → RIR 안내 문구로 교체 (D9) |

### Q8. 4주 동안 어떻게 진행하나?

> ✅ **2026-08-14 확정: 루틴 단위는 "주기당 N일"(N = 사용자가 고른 1~7)이고 4주기 반복한다.**
> Day 1~28 폐기. **요일 고정도 아님** — 채워진 일수만큼만 Day 1..N 을 저장하고,
> 언제 수행할지는 사용자 자유다.

| | |
|---|---|
| **결정** | 생성·저장 단위 = **Day 1..N (N행만, 휴식일 행 없음)**. `day_order`는 주기 내 순서이지 요일이 아님. 4주 반복은 데이터 복제가 아니라 조회 규칙 |
| **진행(점진 과부하)** | 주차 배율(×0.8→×1.1) 폐기. **RIR 처방이 점진 과부하를 자체 내장** — "2회 남기고 멈추는 무게"는 힘이 늘면 무게가 저절로 올라가는 자가조절 방식(Zourdos 2016)이라, 같은 주기를 반복해도 부하는 사용자 능력을 따라 증가함 |
| **근거** | ACSM 점진적 과부하 원리를 배율(코드)이 아니라 RIR(자가조절)로 구현. 4주기 후 = **재촬영·재분석 루프** (진단→루틴→재진단이 우리 차별점) 유지 |
| **오늘의 루틴** | **이번 주기에서 다음 미완료 Day** — `완료 수행 횟수`로 계산: `day_order = (완료수 mod N)+1`, `주기 = (완료수 div N)+1`. 요일 무관이라 하루 밀려도 안 깨짐 |
| **회복 간격** | 요일 고정이 주던 회복 보장이 없어지므로 **Day 순서 배치로 흡수** — 인접 Day가 같은 근육군을 겹치지 않게 템플릿 순서 설계(상→하→상) + "연속 이틀보다 하루 간격 권장" 안내 문구 |
| **안전(L3)** | 통증 피드백 → 해당 부위 부하 운동 제외 + 금기 누적 + "지속 시 전문가 상담" 안내. 전 화면 "의학적 조언 아님" 고지. 기존 확정 사항 유지 |
| **⚠️ 스키마 영향 (A 협의)** | `day_routine`(1~28)·`week_number` 폐기 → **`routine_day` N행 구조.** 초안: `docs/routine-schema-draft.md` |

| **H4** | 템플릿 세트·횟수 수치의 출처 미표기 | 수치 자체는 ACSM 권고 부합 확인 → 코드 주석에 출처 명기 |

| **H6** | 템플릿 근육군(한글) ↔ API `targetMuscles`(영문) 미매핑 | 매핑 테이블 코드 고정 (§3) |
| **H7** | 좌우 비대칭→단측 운동의 근거 수준 | RCT 아님을 명시. 화면 문구도 "권합니다"까지만 |
| **H8** 🔴 | **BMI 1차 판정이 근육형을 오분류** — CUT은 인바디가 있어야 발동하는데, 인바디가 있으면 체지방률을 이미 알고 있다. 그런데 BMI를 먼저 보게 해놔서 **BMI 26·체지방 12% 사용자가 CUT으로 떨어짐** | **판정 순서 반전** (아래 상세) |

### H8 상세 — 왜 순서를 뒤집어야 하나

**모순**: CUT 판정은 인바디가 있을 때만 발동함 → 그 시점에 체지방률을 이미 알고 있음
→ 그런데 지방의 **대리 지표(BMI)**를 직접 측정값(체지방률)보다 먼저 본다.
근거의 강도 순서가 뒤집혀 있었다.

**오분류가 양방향으로 발생**:

| 사용자 | BMI 1차 (구) | 체지방률 1차 (신) | 정답 |
|---|---|---|---|
| 근육형 (BMI 26, 체지방 12%) | **CUT** ❌ | BALANCE ✅ | 감량 불필요 |
| 마른비만 (BMI 22, 체지방 28%) | BALANCE ❌ | **CUT** ✅ | 감량 필요 |

→ 순서 반전은 **거짓양성(근육형에게 감량)만 막는 게 아니라 거짓음성(마른비만 놓침)도
같이 잡는다.** 우리 서비스가 인바디를 받는 이유 자체가 "겉으로 안 보이는 체성분"인데,
BMI를 먼저 보면 그 강점을 스스로 버리는 셈이었다.

**폴백 체인** (체지방률 필드를 OCR이 못 읽었을 때):

```
1차  body_fat_percentage           직접 추출값
2차  body_fat_mass ÷ weight × 100  파생값 — 결과지에 둘 다 있어 동시 실패 확률 낮고,
                                   ocr.py 가 이미 이 항등식으로 검증 중이라 일관됨
3차  BMI ≥ 25                      최후 보조. ⚠️ 근육형 오분류 가능 — 이 경로로
                                   판정됐음을 job.result 에 남겨 추적 가능하게
```

**근거가 오히려 강해짐**: 대한비만학회 지침도 BMI가 근육량을 반영하지 못하는 한계를
명시한다. 따라서 **"실측 체성분이 있으면 그것을 우선하고, 없을 때만 BMI로 보조한다"**
가 지침의 취지에 더 부합한다. 데모에서 "근육 많은 사람한테 감량 모드 주는 앱"이라는
지적을 받을 여지도 사라진다.

| 대퇴사두 | QUADRICEPS | UPPER LEGS |
| 햄스트링·둔근 | HAMSTRINGS · GLUTEUS MAXIMUS | UPPER LEGS, HIPS |
| 종아리 | GASTROCNEMIUS · SOLEUS | LOWER LEGS |
| 코어 | RECTUS ABDOMINIS · OBLIQUES | WAIST |
| (CUT 유산소) | — | CARDIO |

**진단 부위 → 슬롯 연결** (L2 가중이 흐르는 경로):
Torso→가슴·등·어깨·코어 / Upper_Arm→이두·삼두 / Lower_Arm→팔(전완 포함 운동) /
Upper_Leg→대퇴사두·햄스트링·둔근 / Lower_Leg→종아리

**운영**: 배치 1회 수집 → 로컬 캐시 (시연 중 외부 API 장애 차단, rate limit 회피).
운동명 한글화도 배치 시 1회 번역 후 캐시.

## 4. 전체 흐름 (최종)

```
[코드]  주당 일수(사용자) ──→ L1 분할 템플릿                    (ACSM 2009)
[코드]  인바디 체지방률(1차) ──→ L0 모드 CUT/BALANCE            (JCEM·Donnelly, BMI는 폴백)
[코드]  F09 priority_parts ──→ L2 슬롯별 세트 가산, 상한 20     (Schoenfeld 2017)
[코드]  ExerciseDB 캐시 ──→ 슬롯별 후보 필터 + 복합운동 우선     (ExerciseDB·ACSM)
[LLM ]  후보 안에서 exerciseId 선택 (1회 호출)                  ← 유일한 LLM 단계
[코드]  RIR 문구 부여 · L3 금기 제외                             (Zourdos·ACSM)
        → routine_day N행(주기 내 순서, 휴식일 없음) + 운동 목록
          4주기 반복·오늘의 Day 는 조회 규칙 (완료 수행 횟수 기반)
```

LLM 호출은 여전히 1회이고, 이제 그 1회조차 "무엇을 골라도 맞는" 집합 안입니다.

### 5-1. D10 배경 — "비교 가능 부위만 추천" 원칙과 BALANCE 사용자

**체지방률이 기준 미만인 사용자(BMI 수치와 무관)는 BALANCE 모드로 기존 확정 방식
그대로 갑니다.** ⚠️ BMI 23이라도 체지방률이 남 25%↑면 CUT입니다 (§2-H8 마른비만).
그리고 "비교 가능 부위만 추천" 원칙은 이미 구조적으로 지켜지고 있습니다 —
템플릿의 모든 슬롯이 비교 가능 9부위에 매핑되기 때문입니다
(가슴·등·어깨·코어→Torso / 팔→Arm×4 / 대퇴사두·햄스트링→Upper_Leg / 종아리→Lower_Leg).
9부위가 주요 근육군 전부를 커버하도록 선정됐으므로 "전신 루틴" = "비교 부위 루틴"입니다.

원칙이 실제로 시험대에 오르는 건 **이번 세션에서 진단에 실패한 부위**(옷 가림+인바디
없음, 세그 탈락)뿐입니다. 추천의 근거가 두 종류라는 걸 인정하면 해석이 정리됩니다:

| 추천 종류 | 근거 | 적용 범위 |
|---|---|---|
| 기초 처방 (기본 볼륨) | ACSM/WHO 가이드라인 | 전신 — 누구나 받는 표준 |
| 개인화 (가중 + 문구) | F08/F09 진단 + 인바디 | **비교분석 성공 부위에만** |

**B(기본 볼륨 유지)를 권하는 근거**: ① WHO/ACSM 모두 "모든 주요 근육군" 대상 근력을
권고 — 일부만 시키면 우리가 근거 삼는 가이드라인을 스스로 위반 ② 길항근 균형 —
밀기만 있고 당기기가 없는 루틴은 자세 문제를 만듦 ③ "판단 못 함"≠"운동 불필요" —
진단 실패는 부위 상태의 정보가 아니므로 처방 근거로 쓸 수 없음.
화면 문구로 구분: 진단 부위 "왼팔이 부족해서 더 넣었어요" / 실패 부위 "확인하지
못해 표준 구성으로 넣었어요" — 개인화를 주장하지 않으므로 원칙 위반이 아님.

⚠️ A(제외)를 택할 경우의 부작용도 논의 필요: 옷을 많이 입을수록 루틴이 앙상해지고,
최악의 경우 3부위짜리 4주 루틴이 나옴.

## 6. "어떻게 운동을 추천하나요?" — 최종 답변 스크립트

> "네 단계입니다. 첫째, **몇 번 운동할지는 사용자가 정합니다** — 총 운동량이 같으면
> 빈도는 결과에 차이가 없다는 메타분석이 있어서, 지속할 수 있는 요일 수가 더 중요합니다.
> 둘째, **구조는 ACSM 가이드라인**대로 코드가 짭니다 — 초보자는 전신 2~3회, 세트와
> 횟수도 권고 범위(3세트 8~15회) 안입니다. 셋째, **어디를 강조할지는 체형 진단과
> 인바디가 정합니다** — 약점 부위에 주당 2~4세트를 더하는데, 이것도 볼륨-근성장
> 용량반응 연구 범위 안입니다. 체지방이 높으면 — 인바디 실측 기준으로만 — 전신+유산소
> 모드로 바뀌는데, 부위 운동으로 부위 살을 뺀다는 주장(spot reduction)은 과학적으로
> 부정돼 있기 때문입니다. 넷째, **구체적 운동은 ExerciseDB 1,500여 개에서 코드가
> 조건(근육·장비·난이도)에 맞게 거른 후보 중에서 AI가 고릅니다.** AI는 목록 밖 운동을
> 낼 수 없어서 없는 운동을 지어내는 일이 구조적으로 불가능합니다. 무게는 저희가 추정할
> 수 없으므로 추정하지 않고, '2회 남기고 멈추는 무게'라는 검증된 자가조절 방식으로
> 안내합니다."
