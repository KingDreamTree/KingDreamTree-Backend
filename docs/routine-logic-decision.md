## 0. 한 줄 요약

> **"살부터 빼야 하는 몸 vs 부위별 추천" 충돌은 가짜 충돌입니다.**
> 부위 운동으로 그 부위 살이 빠지지 않는다는 것(spot reduction 부정)이 학계 다수 결론이므로,
> **"뺄 것인가"는 체지방(인바디)이 정하는 전역 모드**이고, **부위 진단은 어느 모드에서든
> 근력 운동의 가중치**로 살아남습니다. 서로 다른 층위라 우선순위를 다툴 일이 없습니다.

---

## 1. 왜 충돌이 아닌가 — 과학적 근거

### 1-1. 부위 운동 ≠ 부위 지방 감소 (spot reduction)

| 연구 | 결론 |
|---|---|
| 복부 운동 6주 RCT (Vispute 2011) | 복부 지방 변화 없음. 복부 근지구력만 향상 |
| 한 다리 지구성 훈련 12주 (Ramírez-Campillo 2013) | 훈련한 다리의 국소 지방 감소 없음 (DEXA) |
| **체계적 문헌고찰 + 메타분석 (2021)** | 국소 운동이 국소 지방을 줄인다는 증거 없음 |
| 반론: 복부 유산소 RCT (Brobakken 2023) | 복부 지방이 더 줄었다는 단일 반론 존재 — 소수 견해 |

→ **"팔이 얇으니 팔 운동으로 팔 살을 정리한다"는 논리는 세울 수 없습니다.**
반대로 **"팔이 얇으니 팔 근육을 키운다"는 논리는 유효합니다** (근비대는 국소적).
그래서 부위 진단은 *지방*이 아니라 *근육*에 대한 처방 근거로만 씁니다.

### 1-2. 지방 감량은 전신 에너지 수지 문제

- WHO 2020: 주당 **유산소 150~300분(중강도)** + **주 2회 이상 전신 근력** 권고
- 감량기에 근력 운동을 병행해야 제지방(근육)이 보존됨
- **초보자는 유산소+근력 병행(concurrent training) 간섭 효과가 사실상 없음** —
  메타분석 다수. "유산소가 근성장을 방해한다"는 걱정은 숙련자 이야기

### 1-3. 주당 빈도

- Schoenfeld 2016 메타분석: 근육군당 **주 2회**가 주 1회보다 우수
- Schoenfeld 2019 업데이트: **총볼륨이 같으면 빈도 자체는 무관** → 빈도는 사용자
  라이프스타일에 맞추고, 볼륨 배분은 코드(템플릿)가 책임지면 됨
- ACSM: 근력 최소 주 2회

→ **기존 결정(사용자가 1~7일 선택, 템플릿이 볼륨 배분) 그대로 유지해도 근거가 섭니다.**
권장 표시만 3일에 붙이면 됩니다.

## 2. 타 서비스는 어떻게 하나

| 서비스 | 방식 | 우리와의 시사점 |
|---|---|---|
| **Fitbod** (美, 근력 특화) | 근육군별 회복도(freshness)를 추적해 덜 회복된 근육을 피하고, 과사용된 근육군의 볼륨을 다른 곳으로 이동. 분할(PPL 등)은 구조로 강제 | "부위는 가중치, 구조는 시스템" — 우리 L1/L2 분리와 동일 철학 |
| **Planfit 플랜핏** (韓) | 목표·장비·기록 기반. 7,000만+ 세트 데이터로 세트/횟수/중량 최적화 | 목표(감량/근비대)를 **먼저** 받고 부위는 그 안에서 처리 |
| **Freeletics / NTC** | 온보딩에서 목표(감량/근력/체력) 선택 → 프로그램 골격이 결정됨 | 목표 모드가 최상위 분기라는 업계 공통 패턴 |
| 공통점 | ① 목표 모드가 최상위 ② 장비 필터 필수 ③ **"부위 지방 타겟"을 내세우는 서비스는 없음** | 스팟 리덕션은 마케팅으로도 방어 불가능한 주장 |

## 3. 제안 — 기존 3계층 위에 L0(모드) 한 층만 추가

```
L0 목표 모드   [신규]  인바디 체지방률 → CUT(감량) | BALANCE(균형)     ← 코드
L1 골격        [기존]  주당 일수 → 분할 템플릿 (모드별로 골격이 달라짐)  ← 코드
L2 강조        [기존]  부위 진단(F08/F09) → 약점 부위 볼륨 가산          ← 가중치
L3 제외        [기존]  통증·금기 → 대체 운동                            ← 안전
```

### L0 판정 규칙 (코드, 결정론적)

| 조건 | 모드 | 골격 |
|---|---|---|
| 체지방률 ≥ 남 25% / 여 30% (한국 비만 기준) | **CUT** | 전신 근력 + 유산소 결합 |
| 그 외 / **인바디 없음** | **BALANCE** | 기존 분할 템플릿 그대로 |

- 인바디 없으면 BALANCE — 시각 추정만으로 "감량부터 하세요"라고 말하지 않습니다
  (체지방률은 사진으로 신뢰성 있게 못 잽니다. 실측 있을 때만 모드를 바꾸는 게 방어 가능)
- F09 요약에는 모드 근거를 명시: "체지방률 27%로 감량 병행이 효과적이라 전신 루틴으로 구성했어요"

### CUT 모드 골격 (예: 주 3일)

```
Day 1  전신 근력 A (40분) + 유산소 마무리 15분
Day 2  휴식 (걷기 30분 권장 — is_rest지만 안내 문구)
Day 3  전신 근력 B (40분) + 유산소 마무리 15분
Day 4  휴식
Day 5  전신 근력 C (40분) + 유산소 마무리 15분
Day 6~7 휴식 (주말 중 하루 가벼운 유산소 권장)
```

- 근력을 빼지 않는 이유: 감량기 제지방 보존 (§1-2). "감량 = 유산소만"이 아님
- **L2(부위 가중)는 CUT 모드에서도 동작** — 전신 근력일의 운동 선택에서 약점 부위
  운동이 먼저 뽑힘. 부위 진단이 버려지지 않습니다

## 4. ExerciseDB API 연동 설계

### 4-1. 부위 매핑 (Sapiens 9부위 → API bodyParts)

| 우리 진단 부위 | API bodyParts | 비고 |
|---|---|---|
| Torso | CHEST, BACK, WAIST, SHOULDERS | 몸통은 앞뒤+어깨 전부 |
| Left/Right_Upper_Arm | UPPER ARMS | |
| Left/Right_Lower_Arm | LOWER ARMS | |
| Left/Right_Upper_Leg | UPPER LEGS, HIPS | 샘플의 HIPS 확인됨 |
| Left/Right_Lower_Leg | LOWER LEGS | |
| (CUT 유산소 슬롯) | CARDIO | 진단 부위 아님, 모드가 소환 |

- ⚠️ **좌우 구분이 API에 없음** → 좌우 비대칭이 클 때는 이름/keywords 에서
  단측(single-arm, lunge, one-leg) 운동을 필터해 배치
- ⚠️ 실제 enum은 `GET /bodyparts` 로 **확정 필요** (위 표는 샘플+공개 문서 기반 추정)

### 4-2. LLM 역할 축소 — 운동을 지어내지 못하게

```
[배치]  API 운동 풀 → 로컬 캐시 (이름·bodyParts·equipments·type·imageUrl)
                     매 사용자 요청마다 API 호출하지 않음 (비용·rate limit·장애 차단)
[코드]  모드+템플릿 슬롯별 후보 필터 (bodyParts + 장비 + STRENGTH/CARDIO)
[LLM]   후보 목록 **안에서만** 선택 + 세트/횟수/휴식 결정 (exerciseId 반환)
[코드]  4주 복제 + 주차 배율 + L3 금기 제외
```

- LLM에 후보 풀을 주고 그 안에서 고르게 하면: ① 존재하지 않는 운동 환각 차단
  ② exerciseId 가 연결되어 **운동 이미지/영상 표시 가능** ③ 검증 가능
- 운동명 한글화: 배치 시 LLM 번역 1회 → 캐시에 저장 (요청 시마다 번역 안 함)

### 4-3. 스키마 영향 (A 와 협의 필요)

- `day_routine_exercise` 에 `exercise_ref`(API id) · `image_url` 컬럼 추가 여부
- 운동 캐시를 테이블(`exercise_catalog`)로 둘지 JSON 파일로 둘지

| # | 질문 | B 제안 | 결정 |
|---|---|---|---|
| **D1** | 목표 모드(L0) 도입? 기준은? | 도입. 체지방률 남 25%/여 30% (한국 비만 기준). **인바디 없으면 BALANCE** | ☐ |
| **D2** | 주당 일수 UX | 기존대로 사용자 선택(1~7) + **"권장" 배지를 3일에** | ☐ |
| **D3** | CUT 모드 유산소를 루틴 슬롯으로 넣나, 안내 문구만 넣나 | **슬롯으로** (CARDIO 타입 운동 배치). 문구만 넣으면 아무도 안 함 | ☐ |
| **D4** | 감량/근비대/균형 3모드? | MVP는 **2모드(CUT/BALANCE)**. 근비대는 BALANCE에 흡수 | ☐ |
| **D5** | 장비 필터 | 온보딩에 "헬스장/홈트" 1문항 추가 → equipments 필터 | ☐ |
| **D6** | API 캐싱 | 배치 1회 수집 → 로컬 캐시. 시연 중 외부 API 장애 원천 차단 | ☐ |
| **D7** | 운동명 언어 | 배치 시 한글화 1회 + 캐시 (예: "행잉 레그 레이즈") | ☐ |

### 프론트 전달 사항 (결정 후)

- 온보딩 +1 문항 (장비)
- 루틴 화면에 운동 이미지(imageUrl) 표시 가능해짐
- CUT 모드일 때 "왜 전신 루틴인지" 안내 문구 노출 위치

## 6. 서비스 설명 논리 (심사·투자 대응용 요약)

> "저희는 부위별 진단을 하지만 **부위별로 살을 빼준다고 주장하지 않습니다.**
> 그건 과학적으로 부정된 주장(spot reduction)이라서요.
> 대신 체지방이 높으면 — 인바디 실측 기준으로만 — WHO 가이드라인에 따라
> 전신 근력+유산소 루틴을 주고, 부위 진단은 그 안에서 **어떤 근육을 먼저
> 키울지의 가중치**로 씁니다. 운동은 ExerciseDB 1,500+개 풀에서 코드가
> 후보를 거르고 LLM은 그 안에서만 고르므로 없는 운동을 지어낼 수 없습니다."
