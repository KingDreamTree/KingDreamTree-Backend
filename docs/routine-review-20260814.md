# F10 루틴 로직 — 외부 리뷰 대응 (2026-08-14)

> GPT·Gemini 리뷰 10+4건을 현재 코드에 대조해 **채택 7 / 반박 3 / 보류 4** 로 정리했다.
> 검증: `python scripts/verify_routine_rules.py` (불변식 40여 항목, 전부 통과)

## 1. 설계 — 왜 이 구조인가

### 한 문장

> **LLM 의 재량에 근거를 요구하지 않는다. 재량 자체를 없앤다.**

"왜 이 운동인가요?"에 "AI가 골랐어요"는 답이 아니다. 그래서 추천의 모든 단계를
둘 중 하나로 만들었다.

| | 내용 |
|---|---|
| **(a) 출처 있는 결정론적 규칙** | 가이드라인·논문에서 옴. 코드가 실행 |
| **(b) 무엇을 골라도 틀리지 않는 후보 집합 안에서의 선택** | LLM 이 담당 |

### 계층

```
[입력]  운동 일수 N · 인바디(선택) · 체형 진단(선택)
   ↓
L0 모드     체지방률 → CUT | BALANCE          [코드·결정론]
   ↓
L1 골격     N → Day 1..N 슬롯 확정            [코드·템플릿]
   ↓
L2 개인화   약점 부위 → 볼륨 가중 + 후보 편향   [코드·가중 / 프롬프트·태그]
   ↓
L3 후보     카탈로그 필터 → 슬롯별 후보 목록    [코드·필터]
   ↓
   선택     후보 중 exercise_ref 하나          [LLM 1회]
   ↓
   검증·조립  후보 밖 폐기 → 1순위 대체         [코드]
```

**핵심 불변식 — 진단은 가중치이지 구성 요소가 아니다.** 진단이 없어도, 실패해도,
옷에 가려도 루틴은 항상 완성된다. 진단이 하는 일은 이미 존재하는 슬롯의 세트를
올리고 후보 정렬을 기울이는 것뿐이다.

### 수치의 출처

| 항목 | 값 | 근거 |
|---|---|---|
| 분할 | 초보 전신 2~3일, 4일+부터 분할 | ACSM 2009 Position Stand (PMID 19204579) |
| 세트·횟수 | 초보 1~3세트 × 8~12회 | 같은 문서 |
| 코어·종아리 15회 | 근지구력 범위 | 같은 문서 (15~25회) |
| 빈도 | 총볼륨 같으면 빈도 무관 | Schoenfeld 2019 (PMID 30558493) |
| 볼륨 용량-반응 | ~10세트/주까지 뚜렷 | Schoenfeld 2017 (PMID 27433992) |
| 유산소 | 감량 시 주 150분+ | ACSM Donnelly 2009 |
| 점진 과부하 | RIR 자가조절 | Zourdos 2016 |

> 빈도가 근성장과 무관하다는 근거가 있어서 **일수를 사용자에게 맡길 수 있다.**
> 볼륨 배분은 코드가 책임진다. 이 분리가 L1 의 존재 이유다.

## 2. 채택 — 고친 것 7건

### ① BMI 폴백으로 CUT 보내지 않는다 (GPT #1) 🔴

**문제.** 체지방률을 못 읽으면 BMI ≥ 25 로 CUT 판정했다. BMI 는 지방의 **대리
지표**다. 직접 측정값을 못 읽은 상황에서 대리 지표만으로 감량을 처방하면,
`routine_mode` 상단에 스스로 적어둔 근육형 오분류(BMI 26 · 체지방 12%)를
우리가 만들어낸다. 체지방률 1차 원칙을 세우고 폴백에서 그 원칙을 뒤집는 구조였다.

**수정.** 체지방률이 없으면 **무조건 BALANCE**. BMI 는 계속 계산해 `value` 에
담지만 판정에는 쓰지 않는다. `basis` 를 `BMI_FALLBACK` → `BODY_FAT_UNAVAILABLE` 로 바꿔
"판정에 안 썼다"를 이름으로 드러냈다.

**근거.** 오분류의 해로움이 비대칭이다. CUT 을 놓치면 근력 루틴을 받을 뿐이지만,
불필요한 CUT 은 근육형 사용자에게 유산소를 강제한다. 확신이 없으면 기본값이 안전하다.

### ② 볼륨 가중 예산을 근육군 단위로 (GPT #6) 🔴

**문제.** 예산이 *부위(part)* 별로 독립 4세트였다. 실측:

```
Left_Upper_Arm + Right_Upper_Arm 이 둘 다 우선 부위
→ 둘 다 ("이두","삼두") 에 매핑
→ 이두 3 → 5, 삼두 3 → 5   (각각 +2 이중 가산)
```

**수정.** 예산을 근육군 단위로 공유. 3중 상한으로 정리했다.

| 상한 | 값 | 단위 |
|---|---|---|
| `WEEKLY_BOOST_CAP_PER_GROUP` | 4 | 근육군당 추가 세트 |
| `WEEKLY_GROUP_SET_CAP` | 20 | 근육군 주간 총 세트 |
| `slot_sets_cap()` | 복합 4 / 고립 5 | 슬롯 하나 |

**근거.** 진단 feature 는 좌우로 갈리지만 **운동은 좌우를 함께 한다.** 예산은
진단 단위가 아니라 실제 볼륨이 쌓이는 단위로 잡아야 한다.

> `20세트` 는 **생리학적 절대 상한이 아니라 MVP 운영 상한**이라고 주석에 명시했다
> (GPT #6 후단 지적 반영). Schoenfeld 2017 은 ~10세트/주까지 뚜렷한 반응을 보고
> 그 이상은 근거가 얇아진다고 본다.

### ③ 슬롯 세트 상한을 복합/고립으로 분리 (Gemini #1)

**문제.** `SLOT_SETS_CAP = 5` 일괄. 이두 컬 5세트는 괜찮지만 스쿼트 5세트는
초보 세션을 무너뜨린다.

**수정.** 복합 다관절이 주로 배치되는 근육군(가슴·등·어깨·대퇴사두·햄스트링)은 4,
고립(이두·삼두·종아리·코어)은 5.

**근거.** 어느 운동이 올지는 LLM 선택 뒤에 정해지지만 **근육군은 코드가 이미
확정**했으므로 슬롯 단계에서 결정할 수 있다.

### ④ 5일차 "약점 보완 Day" 제거 (GPT #4) 🔴

**문제.** 원칙 위반이었다. "진단은 가중치일 뿐 포함/제외가 아니다"(D10)라고
해놓고, 5일 분할에 슬롯이 빈 Day 를 두고 `priority_parts` 로만 채웠다. **진단이
Day 하나의 구성 전체를 결정**했다.

**수정.** `("약점 보완", [])` → `("전신 마무리", _FULL_C)`. 전신 골격을 깔고 L2
가중만 얹는다. `build_weak_point_day()` 는 삭제했다.

**효과.** 진단이 없어도 5일차가 성립한다. 검증에 `진단 없이도 골격 성립` 규칙으로 고정.

### ⑤ 4일 하체 A/B 분리 (GPT #8)

**문제.** 상체는 A/B 인데 하체만 같은 Day 가 두 번이었다.

**수정.**

```
하체 A = 대퇴사두 dominant   (대퇴사두 4 · 햄스트링 3)
하체 B = 햄스트링·둔근 dominant (햄스트링 4 · 대퇴사두 3)
```

주동근을 다르게 두면 같은 주에 두 번 해도 회복이 겹치지 않고, 후보 정렬이
`targetMuscles` 1순위라 **운동 선택도 자연히 갈린다.** 5일 분할도 함께 적용.

### ⑥ CUT 유산소 150분 서술 정정 (GPT #7)

**문제.** 주석은 "주 150분에 도달시킨다"인데 코드는 15분 × 3일 = **45분**이었다.

**수정.** 루틴이 보장하는 것과 안내로 채우는 것을 분리해 서술.

```
루틴 보장:  근력일당 15~20분 (주 3일이면 45분)
안내 영역:  일상 활동·걷기 (CUT_NOTICE)
실제 처방:  "주간 활동량을 점진적으로 늘린다"
```

### ⑦ 유산소 순서 회귀 테스트 추가 (Gemini #2)

**사실관계.** 순서는 **이미 보장되고 있었다.** `get_template()` 이 `append` 로
붙이므로 유산소는 항상 마지막이다. 전 일수(1~7) 실측 확인.

**다만 지적은 유효하다** — 검증이 없었다. 누가 `insert` 로 바꾸면 조용히 깨진다.
`rule_cardio_last()` 로 못 박았다.

**근거.** 유산소를 먼저 하면 글리코겐이 고갈된 상태로 근력을 하게 되어 수행 능력과
근비대 신호가 함께 떨어진다.

## 3. 반박 — 사실관계가 다른 것 3건

### GPT #2 "L2 가 사실상 +1세트뿐이다" → **아니다**

L2 는 이미 운동 **선택**까지 관여한다.

| 경로 | 코드 |
|---|---|
| 볼륨 가중 | `apply_weakness_boost()` |
| 후보 편향 | `_collect_candidates(prefer_single_side=)` — 좌우 비대칭 부위는 단측 운동 우선 |
| 선택 유도 | 프롬프트에 `focus={part}` 태그 → "그 부위에 가장 직접적인 운동을 고르라" |

GPT 가 요구한 구조(`체형 Feature → priority muscle group → 해당 운동 후보 우선 선택
→ 볼륨 가중`)가 이미 그대로 구현돼 있다.

### GPT #3 "ExerciseDB 매핑 계층이 필요하다" → **이미 있다. 그리고 우선순위가 반대다**

2계층으로 분리돼 있다.

```
SLOT_BODY_PARTS     bodyParts 로 후보를 **거른다** (넓게)
SLOT_TARGET_MUSCLES targetMuscles 로 **줄 세운다** (정밀하게)
```

GPT 는 "targetMuscles 를 bodyParts 보다 우선"이라 했지만, 실측 결과 그 반대가 맞다.
`bodyParts` enum 이 추정과 여러 곳 달라 표준 문서로 확정했고, `bodyParts` 만으로는
이두/삼두를 못 가른다(둘 다 `UPPER ARMS`). 그래서 **거르기는 bodyParts, 줄세우기는
targetMuscles** 다. 필터를 targetMuscles 로 하면 후보가 과하게 좁아진다.

### GPT #5 "진단 부위만 운동하는 구조 금지" → **이미 그렇다**

D10 으로 확정돼 있고, ④를 고치면서 마지막 예외까지 없앴다. 검증 규칙으로 고정했다.

### `training_experience` 를 도입하지 않는 이유 (확정)

**서비스 타깃이 운동 초보자다.** 중급자를 고려할 필요가 없으므로 숙련도 분기 자체가
불필요하다. 이 결정은 여러 곳을 동시에 단순하게 만든다.

| 항목 | 초보 고정이라 생기는 결론 |
|---|---|
| `MAX_WEEKLY_REPEAT = 2` | **그대로 둔다.** Gemini #3 은 "초보는 같은 종목을 주 3회 반복하는 게 자세 학습에 유리하다"고 했지만, 이는 **종목 수를 줄이자**는 뜻이지 상한을 풀자는 뜻이 아니다. 현재 후보 정렬이 이미 복합·머신·덤벨을 1순위로 올려 **기본 종목이 반복 선택되는 구조**다. 상한을 풀면 LLM 이 한 종목만 6번 뽑아 주간 자극이 한쪽으로 몰릴 수 있다 |
| 세트·횟수 | ACSM 초보 권고(1~3세트 × 8~12회) 하나만 유지. 중급 구간을 만들 필요 없음 |
| 분할 | 4일+ 분할도 초보 기준 볼륨으로 고정. 중급용 고볼륨 변형 불필요 |
| `WEEKLY_GROUP_SET_CAP = 20` | 초보 기준 보수적 운영 상한으로 계속 유효 |
| 운동 후보 | `is_beginner_safe()` 필터를 **전 사용자에 항상 적용**한다. 예외 경로가 없어 검증이 단순해진다 |

> 입력을 하나 안 받는 게 아니라, **분기 자체가 사라진다.** 온보딩 문항도, 숙련도별
> 상수 세트도, 그 조합에 대한 검증도 필요 없다. 나중에 중급을 열게 되면 그때
> `RoutineMode` 처럼 StrEnum 하나를 추가하면 된다.
